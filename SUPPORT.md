# Support

Limes Axis is an early commercial product in a private repository. Repository
support for authorized collaborators is maintainer best-effort; it is not a
production support agreement or response-time commitment.

## Where to Ask

- Use a GitHub issue for reproducible bugs, documentation gaps and focused
  feature proposals.
- Search existing issues before opening a new one and link related discussions.
- Include the affected revision, environment, expected behavior, actual behavior
  and the smallest safe reproduction.
- Use the issue templates when available so maintainers receive the evidence
  needed to triage the report.

## Sensitive Reports

Do not put vulnerabilities, credentials, tokens, customer data, personal data or
proprietary logs in an issue. Follow [SECURITY.md](./SECURITY.md) and use GitHub
private vulnerability reporting when available.

For conduct or moderation incidents, contact a repository maintainer privately
through the GitHub organization or repository contact surface. Do not publish
personal or sensitive evidence in an issue.

## Support Boundary

Maintainers may ask for a minimal reproduction before investigating. Repository
support covers the checked-in evaluation runtime and documentation. Customer-
specific deployment, operational SLA, private integrations and incident response
are outside the repository support commitment unless a separate agreement says
otherwise.

Diagnostic output must be redacted before sharing. Prefer public-safe readiness,
audit and support-diagnostics responses over raw database rows, environment
variables or provider payloads.
